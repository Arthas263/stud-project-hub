# Технічні вимоги до проєкту «Облік студентських проєктів»

## 1. Призначення системи
Веб-застосунок **Student Projects Hub** розробляється для автоматизації обліку, каталогізації та оцінювання студентських навчальних і кваліфікаційних проєктів. Система замінює ручне ведення таблиць на зручний веб-інтерфейс із розмежуванням прав доступу та пошуком у реальному часі.

---

## 2. Ролі користувачів
| Роль | Опис повноважень та доступні дії |
|------|----------------------------------|
| **Гість / Студент** | Перегляд публічного каталогу проєктів, пошук за назвою, фільтрація за викладачем чи статусом, перегляд карток проєктів із рецензіями, подання заявки на реєстрацію нового проєкту. |
| **Викладач (науковий керівник)** | Перегляд закріплених за ним проєктів, зміна статусу виконання, публікація рецензій, зауважень та підсумкових оцінок. |
| **Адміністратор** | Повний доступ (CRUD) до довідників викладачів і студентів, модерація поданих заявок, редагування та видалення записів. |

---

## 3. Сутності предметної області (Модель БД)

### 3.1. Сутність `Teacher` (Викладач)
| Атрибут | Тип даних | Опис |
|---------|-----------|------|
| `id` | `INT (PK, AI)` | Унікальний ідентифікатор викладача |
| `full_name` | `VARCHAR(150)` | Прізвище, ім’я та по батькові |
| `department` | `VARCHAR(100)` | Назва кафедри (напр. КСМ) |
| `academic_degree` | `VARCHAR(80)` | Науковий ступінь / вчене звання |
| `email` | `VARCHAR(120)` | Корпоративна електронна пошта |

### 3.2. Сутність `Student` (Студент)
| Атрибут | Тип даних | Опис |
|---------|-----------|------|
| `id` | `INT (PK, AI)` | Унікальний ідентифікатор студента |
| `full_name` | `VARCHAR(150)` | Прізвище, ім’я та по батькові |
| `group_name` | `VARCHAR(20)` | Академічна група (напр. КІ-23-1) |
| `email` | `VARCHAR(120)` | Контактний e-mail |
| `phone` | `VARCHAR(20)` | Номер телефону |

### 3.3. Сутність `Project` (Студентський проєкт)
| Атрибут | Тип даних | Опис |
|---------|-----------|------|
| `id` | `INT (PK, AI)` | Унікальний ідентифікатор проєкту |
| `title` | `VARCHAR(200)` | Тема / назва проєкту |
| `description` | `TEXT` | Детальний опис мети та задач проєкту |
| `teacher_id` | `INT (FK)` | Посилання на наукового керівника (`Teacher.id`) |
| `student_id` | `INT (FK)` | Посилання на автора проєкту (`Student.id`) |
| `status` | `ENUM` | Статус (`draft`, `in_progress`, `review`, `completed`) |
| `repo_url` | `VARCHAR(255)` | Посилання на репозиторій GitHub |
| `created_at` | `DATETIME` | Дата та час реєстрації проєкту |

### 3.4. Сутність `Review` (Рецензія / Відгук)
| Атрибут | Тип даних | Опис |
|---------|-----------|------|
| `id` | `INT (PK, AI)` | Унікальний ідентифікатор рецензії |
| `project_id` | `INT (FK)` | Посилання на проєкт (`Project.id`) |
| `teacher_id` | `INT (FK)` | Посилання на рецензента (`Teacher.id`) |
| `comment` | `TEXT` | Текст відгуку та зауваження викладача |
| `grade` | `TINYINT` | Оцінка за 100-бальною шкалою (`0–100`) |
| `created_at` | `DATETIME` | Дата та час публікації рецензії |

---

## 4. Зв’язки між сутностями
* **Teacher (1) — Project (∞):** один викладач може бути науковим керівником багатьох студентських проєктів.
* **Student (1) — Project (∞):** один студент може виконувати кілька проєктів протягом навчання.
* **Project (1) — Review (∞):** один проєкт може отримати декілька рецензій на різних етапах перевірки.
* **Teacher (1) — Review (∞):** один викладач може залишити багато рецензій на різні проєкти.

## 5. Структура сторінок застосунку
1. **`/` (Головна сторінка)** — презентаційний банер, лічильники статистики (кількість проєктів, керівників, захищених робіт), блок останніх доданих проєктів.
2. **`/projects` (Каталог проєктів)** — перелік усіх проєктів у вигляді карток/таблиці з миттєвим пошуком за назвою та фільтрацією за керівником і статусом.
3. **`/project/:id` (Картка проєкту)** — повна інформація про роботу, дані автора та керівника, клікабельне посилання на GitHub, історія рецензій та оцінок.
4. **`/submit` (Форма подання проєкту)** — інтерактивна форма реєстрації нового проєкту з перевіркою введених даних на клієнті.
5. **`/about` (Про кафедру та контакти)** — довідкова інформація про кафедру та форма зворотного зв’язку.

## 6. Функціональні вимоги
- **F1 (Асинхронність):** Завантаження переліку проєктів, деталей картки та рецензій відбувається асинхронно через REST API без повного перезавантаження сторінки.
- **F2 (Інтерактивна фільтрація):** Пошук за ключовими словами та фільтрація за викладачем/статусом миттєво оновлюють відображуваний список на клієнті.
- **F3 (Валідація форм):** Форма реєстрації проєкту та форма додавання рецензії перевіряють обов’язковість полів, коректність формату e-mail, телефону та валідність URL-посилання на GitHub (`https://github.com/...`).

## 7. Нефункціональні вимоги
- **N1 (Адаптивність):** Інтерфейс коректно відображається на всіх пристроях починаючи від мобільних екранів шириною **360 px** до десктопних моніторів **1280 px+**.
- **N2 (Продуктивність):** Показник продуктивності за аудитом Google Lighthouse Performance становить **≥ 85 балів**.
